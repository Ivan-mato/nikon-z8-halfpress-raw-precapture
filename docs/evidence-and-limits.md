# 证据范围与复现边界

## 静态复核

公开工具从使用者提供的精确原厂包与 MAIN 检查身份，并只生成七个声明的指令修改。另一个工具独立核查允许的修改范围、实际差异字节、完整结果哈希、分支目标与 STURB 编码。

这些是可在干净 Python 环境复核的字节事实。它们不等于控制流在全部状态可达、硬件行为正确、更新包被接受或相机可恢复。

## 历史模型实验

历史数值摘要见 [observations.json](../evidence/observations.json)。第一阶段发布复核没有再次启动固件；在 Windows 上另写程序，重新核对原厂包与 MAIN 的关系、修改位点，并对四份保留的 NEF 完整解码。文件与解码像素摘要均与历史记录一致。该阶段结果保留在 [publication-recheck.json](../evidence/publication-recheck.json)，其中没有重读 WSL 源与 producer 的限制仅描述当时的工作。

随后补充的内容审核重新生成了完整合成源，并核对 WSL 内旧源的完整身份。两份历史首帧 NEF 与该源、各自实际保留的 producer 全样本比较均零差异；两份历史两周期实验的 NEF 只重做源比较，未升级为同次 producer 比较通过。宿主内容工具测试与新三组固件执行分开记载，不能互相替代。

历史三组首帧及两周期实验共用的 QEMU 身份是：

```text
e9177cf4dca57872e7d1e4fb27af82a8d1f3ff65be027b22d36075f98af3a618
```

合成 RAW 输入身份是：

```text
85878e2e56ee0f6bc10cc0d5dd474375e2ee67bc310d24acf955b0fa5efba293
```

模型通过直接映射 MAIN 运行，未执行原厂 loader/更新器。依赖辅助 MCU、合成 ROM、sensor/ISP/codec/storage 功能模型，以及 `0x45A403E7=1`、`0x47F5AF45=1` 和 timed-single 实验选项。合成数据与模型完成事件不是相机传感器或物理编码器的证据。

这是本地修改版 QEMU。与锁定的 RdWing 提交相比，`nikon-z8-lab.c`、`nikon-z8-d980.h`、`full_guest.py` 有差异，包含 engine153 配置寄存器 `off=4` 的接纳规则修改。实验未开启可选宽松开关，不代表这些其他模型修改不存在。第一阶段只核对9个 Nikon overlay 文件，不能据此声称完整源码一致。

本轮将官方 QEMU 压缩包的78,691个普通文件与历史源码逐一比较，补出此前遗漏的 `system/physmem.c`、`accel/tcg/cputlb.c` 观察修改。现在公开的两份补丁、54份上游文件身份和16份准备后 QEMU 文件身份见 [MODEL.md](../runtime/MODEL.md)。观察 hook 的宿主返回地址不能当作固件 PC；关闭环境变量也不能证明 hook 的所有时序影响为零。

## 公开重放入口

现在提供固定源码下载/核对、干净编译、合成源生成、三组独立运行和完整 NEF 审核入口，见 [reproduction.md](reproduction.md)。这补齐了执行流程，不会使历史摘要变成原始日志，也不保证每种主机均能运行。使用者仍需准确原厂包及正确 MAIN 或私有 XOR 表。

新构建不复用历史目标文件。各组使用新卡并记录手势前空闲状态、MCU 实际接收帧、GPIO、完整等待、停止状态和文件数；两组有文件时还必须核对本次 source、producer 与 NEF 全样本对应。同一源摘要不能替代同次 producer 的身份链。源码锁、型号名与二进制哈希用于确定实验身份，不证明硬件准确性。

新编译模型的实际三组首帧结果为1、0、1份 NEF，两份正对照均通过完整内容比较，见 [runtime-reproduction.json](../evidence/runtime-reproduction.json)。MCU 实际交付后分别观察25.184745659、25.276587035、25.105089979秒模型时间。日志中的未建模输出诊断分别为6、1、6条，不能将 `Z8_UNKNOWN=0` 解读为没有模型缺项。

公开内容不含历史或新编译的二进制、原厂固件、原始内存/卡、全部运行日志。不能把上游当前 main 分支替换进来并仍称为同一模型。全新三组首帧结果也不能闭合下面的历史第二周期与真机问题。

## 输入与文件证据的解释

半按两组规定手势均为 `(HALF,FULL): 00 → 10 → 10 → 10 → 00`，MCU 和 GPIO 的 FULL 记录均为 0。启动 MCU 例程本来含 HALF=1/FULL=0，故“仅半按实验”不是声称整个启动期从未半按。手势前另行读出自然释放状态，没有强写清 pending。

原版仅半按的零文件结论来自停机后卡目录，限定于这次输入和时间范围。观察点没有命中不能证明代码没有执行；一次性断点也不能排除重复调用。

内容审核验证 Nikon lossless/F0、14 bit、全部 RAW 样本及三张 JPEG；packed14 producer 与最终压缩 strip 的字节不同是正常层次差别，应比较解码样本。路线4此次审核没有 Adobe 第二解码器结果，不能借用上游另一组实验的结果。

## 失败及未执行实验

- 早期两个正对照驱动因 fixture 相对目录错误中断。修正路径后用新目录执行，旧失败保留。
- 早期原版半按组在手势前触发 `PC 0x40C1FCE4` 写 `0x150C000C = 6`，不能用作有效负对照；后续 `stock-half-002` 才完整完成规定手势。
- 成功首帧两组仍各有六条 `Z8_1508_GROUP` unmodeled-output 日志，不能称没有任何模型缺项。
- 后续两周期中双方都在 `PC 0x40C26848` 写 `0x15432004 = 0x103` 被当前模型 active 状态约束拒绝。两组最终 producer jobs/acks 均为2，文件各为1。两组故障时处于不同释放阶段，不能说末态完全等价。
- 两周期新增文件的图像数据区此前仅按目录定位与旧文件比较；本次发布复核已额外完整解码这两份文件。两份均通过，完整像素摘要与首帧文件一致；没有重新执行同次 producer 比较。
- overlap 实验此前在 QEMU 启动前被当时 WSL 只读文件系统阻止，至今未执行；环境后来可写不改变这项状态，不存在“重叠全按已通过”的结果。

## 真机与持续拍摄

尚无本候选在真实 Z8 上的加载、恢复、动作记录和 NEF。上游其他项目的实机声明不等于这个候选通过。持续半按连拍需在真实选定的原生连拍模式下观察至少两个不同作业及文件，并验证松开后的行为；对于持续半按连拍，目前只有候选方案与验收设计，尚无通过的运行结果。

`bank8[999]` 的 MAIN 重置模板值为0且代码有非1分支。这说明不能仅依据本次模型配置，将1认定为所有 RAW 拍摄的必要条件；非1条件下实际出片仍未验证。`bank5C` 的存储来源已静态定位到 SNOR_USER 区，但当前实际表正文与机身值未知。不能把模型加载的两个字节转成新的真机补丁。
