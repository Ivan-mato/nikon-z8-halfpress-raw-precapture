# 七指令实验修改

仅适用于 README 指定的完整 MAIN 身份；VA 与 MAIN 偏移关系是 `offset = VA - 0x40160000`。完整输入哈希固定原始字节，独立验证器另行解码修改与相关控制流，并输出窗口哈希；它不导入构建器，也不把 manifest 当成验收真理。

| VA | 新指令的语义 | 目的 |
|---|---|---|
| `0x40FD93BC` | `B 0x40FD9420` | 半按排入原生 slot0 后进入逻辑全按电平 case |
| `0x40FD940C` | `B 0x40FD95C0` | 跳过独立物理 full-ID 回调的处理 |
| `0x40FD94BC` | `MOVZ W9, #1` | 为半按释放准备 pending 标志 |
| `0x40FD94C0` | `STURB W9, [X8, #-4]` | 写原生半按释放 pending，无 writeback |
| `0x40FD94C4` | `B 0x40FD9420` | 经原生全按释放 slot2，再处理待定半按释放 slot3 |
| `0x40FDC858` | `MOVZ W0, #0x23` | 忙恢复的 live input 查询由 `0x24` 改为 `0x23` |
| `0x40FDF6C0` | `MOVZ W0, #0x23` | 原生 held-input 重试查询同样改为 `0x23` |

三个无条件分支的有符号 imm26 分别为 25、109、-41；目标以当前指令 VA 加 `imm26 << 2` 计算。STURB 的 imm9 为 `0x1FC`，符号扩展后为 -4；该位置原生入口的 X8 为 `0xA03BD055C`，故写入 `0xA03BD0558`。原函数的 X19/LR 栈帧与原生收尾保持不变。

七个四字节窗口合计覆盖 28 字节，实际不同字节为 21；不能把这两个数混用。代码没有加入新的采集函数、历史帧缓存、安装容器或空函数占位。

## 已知行为条件

- 半按现在请求拍摄，不再只执行原来的准备操作。
- 原始按住重试逻辑仍有门控，不能把它称为已经实现的逐帧连拍入口。
- 新路径跳过原 pending-full-before-half 的一个清零分支。已验收的模型手势从自然释放、pending 为空的状态进入；未证明任意热状态等价。
- 原生忙恢复后的延迟补发可能保留。松开后有在途帧完成与松开后新建请求需分别观察。
- 初始忙掩码不能仅凭“冷启动”假设为零：原厂早期清零之后，按钮注册会再置位。
- 本轮首次释放检查覆盖具体字段和观察时刻；`0xA03BD0608` 的正常释放标记可为 1，不要求整个状态区全零。

## 被原字否定的早期解释

1. 给定事件表中 `0x40FD9B90` 发出的是 `0x18`；`0x40FD9E48` 和 `0x40FDCAF4` 为 `0x1C`。
2. `0x40FDCA00` 位于函数内部；完整入口为 `0x40FDC9C8`。
3. `0x40FE18F4(0x13)` 是有条件的时间戳记录写入，不能称为另一条采集请求。
4. `0x40FD97DC` 注册整个接收者，接口没有事件参数；不能据此实现“额外订阅一个半按事件”。
5. 半按的 `1A/1C` 与全按的 `1B/1D` 使用不同状态和方法；只换按下编号没有处理释放配对。

上述具体否证不等于证明所有未检查路径安全。直接调用扫描也不能排除间接引用。
