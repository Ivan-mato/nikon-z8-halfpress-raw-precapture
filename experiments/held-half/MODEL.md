# Frozen model, provenance and assumptions

`model/` is the exact reduced 80-file model/driver/test snapshot supplied for the 27-frame experiment. Every file is pinned in [source-lock.json](source-lock.json). In particular, `qemu/nikon-z8-lab.c` hashes to `13d296fafecf08c53d49bc1218c66178d53011a40935c9899f7c7a4d64a3f8e8`, and `tools/capture.py` to `6eba789f4de3a6f0c1b76b328f34bbfb343f7eb6573fdedbd156aa6ba58c3be3`. The historical `.contig` and `.bak` source copies are retained for exact snapshot identity; the builder only installs `.c` and `.h` overlay files.

The snapshot derives from [RdWing/z8-qemu](https://github.com/RdWing/z8-qemu), which inherits the [WonderLantern/z9-qemu](https://github.com/WonderLantern/z9-qemu) foundation. Its manifest records inherited Z9 baseline `deb3a75df1795924e9be8f814d9a24ce6b439a67`. **That field does not identify the complete modified Z8 snapshot as an upstream commit.** The full file inventory, not an upstream branch name, defines the model used here. Local changes to multi-frame ownership, completion/rearm and held-half driving are part of this experimental snapshot; they are not attributed to an unmodified upstream release.

The runtime is QEMU 11.1.1. `model/qemu/prepare_source.py` integrates the model and applies inherited DesignWare upper-address DMA-window and SMP breakpoint-removal fixes. The reviewed preparation has 17 changed/added files. Unlike the older `runtime/` recipe, this snapshot does not add that recipe's two write-observer hooks to QEMU core files. The local clean-build review compared the full prepared source trees and build options. It still found different executable bytes, including `.text`; no claim is made that the binary difference is only debug paths.

Relevant implemented contracts include independently tracked alternate RAW/JPEG ports, per-frame buffer ownership and generation, consumed/acknowledged outputs, bounded receiver rearm, DMA/stop acknowledgement and an explicit contiguous-image-bank layout hypothesis. The RAW encoder reads the owned RAM output, writes encoded data, checks it and then signals completion. The multi-frame driver enables `capture-stream-rearm-model`, `engine1540-alternate-bank-model`, `engine153-alternate-bank-model` and `engine15e2-alternate-bank-model`. These are model assumptions and implementations, not recovered silicon specifications.

The exact machine options are generated by the frozen capture driver and recorded in every run's `result.json`. The synthetic startup configuration includes the bank-8 offset-999 byte and selector-5 placeholder. Missing processing coefficients are not reconstructed by the selector. Timed completion is a functional scheduling mechanism; neither these delays nor the displayed release-mode rate have been calibrated to physical capture throughput.

`scripts/guarded_capture.py` wraps the driver's host transport. It permits the declared MCU GPIO/IRQ and model input properties and read/observation/debug-stepping operations, and rejects arbitrary register/memory mutations. It does not edit the frozen model or guest instructions. Its receipts are checked separately from the driver's self-reported success. The guard is an audit aid for the actual driver path, not an adversarial sandbox or proof that the model implements real hardware.

The public audit code reuses the separately written local verification algorithms, with portable paths and an explicit stock/candidate selector. Its assertions are mandatory. All complete RAW comparisons use LibRaw via rawpy; the TIFF/exFAT parsers are separate code, not a second RAW codec.
